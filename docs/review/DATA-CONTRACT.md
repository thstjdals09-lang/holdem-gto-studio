# 데이터 계약 (holdem-hand-review 0.1.0)

타입 원본: `src/review/types.ts`. 이 문서는 같은 내용을 사람이 읽도록 적은 것입니다.

## 1. 단위와 금액

- 한 핸드의 모든 금액은 `unit` 하나로 적습니다: `"chips"`(칩) 또는 `"bb"`(빅 블라인드).
- `bigBlind` 는 그 단위로 잰 BB 크기입니다. `unit` 이 `"bb"` 면 반드시 `1`. 칩 단위에서 모르면 `null` (그러면 BB 환산과 프리플랍 자료 비교를 하지 않습니다).
- 금액은 소수 셋째 자리까지 받습니다. 내부 계산은 정수 milli(× 1000)로 해서 칩 보존을 정확히 검사합니다.
- **추가액과 목표액을 구분합니다.**
  - `add` = 이번 액션으로 **추가로** 넣은 금액
  - `to` = 이번 액션 뒤 **이번 스트리트에서 그 자리가 넣은 누적 금액**(블라인드 포함, 앤티 제외)
  - 둘 다 적으면 `to = (그 자리가 이번 스트리트에 이미 낸 금액) + add` 인지 검사합니다. 하나만 적으면 다른 하나를 계산합니다. 콜은 금액을 생략할 수 있고, 적으면 재구성한 추가 콜과 비교합니다.
  - 예: BB 160 을 낸 BB 가 목표 320 레이즈를 마주하면 추가 콜은 160, 콜 뒤 목표액은 320 입니다. 콜을 `add: 320` 으로 적으면 금액 오류입니다.
- 허용 오차: BB 단위 기록은 소수 둘째 자리 반올림을 고려해 ±0.006BB, 칩 단위는 0.

## 2. 핸드 JSON (`schema: "holdem-review-hand/1"`)

| 필드 | 필수 | 뜻 |
| --- | --- | --- |
| `schema` | ✓ | `"holdem-review-hand/1"` |
| `id` | ✓ | 핸드 식별자 (120자 이내) |
| `complete` | ✓ | 완료 핸드면 `true`. `true` 인데 액션이 남으면 오류 |
| `source` | | `{ kind: "manual" \| "json" \| "lulu-decision-log" \| "example", detail? }` |
| `unit`, `bigBlind` | ✓ | 1절 |
| `buttonSeat` | ✓ | 버튼 좌석 번호 (앉은 좌석이어야 함, 빈 버튼 미지원) |
| `seats` | ✓ | 2~8개 `{ seat, name?, stack }`. 좌석 번호가 커지는 쪽이 시계 방향. `stack` 은 블라인드·앤티를 내기 **전** 초기 스택, 모르면 `null` |
| `seats[].observedStackAfterAnte` | | 가져오기 참고값(앤티를 뺀 관측 스택). 초기 스택으로 쓰지 않음 |
| `hero` | ✓ | `{ seat, cards: ["As","Kd"] \| null }` |
| `forced` | ✓ | 실제로 낸 강제 베팅 `{ seat, kind: "sb" \| "bb" \| "ante" \| "bb-ante", amount }`. 스택이 모자라 덜 냈으면 낸 만큼 |
| `actions` | ✓ | 순서대로 `{ street, seat, type: fold\|check\|call\|bet\|raise, add?, to?, allIn? }` |
| `board` | ✓ | `{ flop?: [3장], turn?, river? }` |
| `showdown` | | 공개된 카드 `{ seat, cards }` — 사후 결과에만 씀 |
| `snapshots` | | 기록된 관측값 `{ beforeAction, pot?, potKind?: "total"\|"settled", toCall?, stacks?: {좌석: 남은 스택}, label? }` — 재구성과 대조만 함 |
| `tournament` | | `{ kind: "standard"\|"satellite", payouts: [1위부터 남은 지급액], otherStacks: [테이블 밖 남은 모든 스택], payoutUnit? }`. 이 테이블이 전체 필드면 `otherStacks: []` |
| `assumptions.ranges` | | `{ 좌석: "22+,A2s+,KTo+" }` 사용자 가정 범위. 결과에 "사용자 가정"으로 표시 |
| `missing`, `notes` | | 확인하지 못한 항목, 메모 |

카드 표기는 랭크 `23456789TJQKA` + 무늬 `cdhs` (`"10h"` 도 받음). 내 카드·보드·쇼다운 사이 중복은 오류입니다. 예제는 `examples/review/`.

### 자리 이름과 행동 순서

- 헤즈업: 버튼 = SB, 프리플랍 먼저·포스트플랍 나중. 이름 `BTN`, `BB`.
- 3~8명: 버튼 다음이 SB, 그 다음이 BB. 프리플랍은 BB 다음 자리부터, 포스트플랍은 버튼 다음 살아 있는 자리부터.
- 이름(프리플랍 순서, 뒷자리 기준): 8명 `UTG UTG1 LJ HJ CO BTN SB BB`, 6명 `LJ HJ CO BTN SB BB`, 3명 `BTN SB BB`.

### 재구성 규칙

| 규칙 | 처리 |
| --- | --- |
| 블라인드 | BB 가 스택이 모자라 덜 내도 다른 자리는 BB 크기 전체를 맞춥니다. 앤티로 스택이 0 이 된 BB 는 블라인드 없이 올인(이때 `bigBlind` 필요) |
| 앤티 | 팟에 들어가지만 추가 콜·최소 레이즈에는 들어가지 않습니다. 개인 앤티는 자리마다 같아 총액으로 층을 나눠도 같고, BB 앤티는 모두의 죽은 돈으로 살아 있는 전원이 자격을 갖는 첫 층입니다 |
| 최소 벳·레이즈 | 벳은 BB 이상, 레이즈 증가분은 마지막 완전 레이즈 크기 이상 (올인이면 모자라도 됨) |
| 짧은 올인 | 완전 레이즈가 안 되는 올인은 이미 행동한 자리에 레이즈를 다시 열지 않습니다. 그 뒤 누적 증가분이 완전 레이즈 이상이면 다시 열립니다 |
| 상대 전원 올인 | 더 베팅할 수 없습니다 (콜·폴드만) |
| 맞춰지지 않은 베팅 | 스트리트가 끝나거나 모두 폴드하면, 가장 많이 낸 자리의 초과분(두 번째로 많이 낸 금액 대비)을 돌려줍니다 |
| 사이드팟 | 살아 있는 자리의 총 투자액 수준마다 층을 나눕니다. 폴드한 자리의 돈은 들어가지만 자격은 없습니다 |
| 칩 보존 | 시작 스택 합 = 남은 스택 + 팟, 팟 층 합 = 팟, 분배 뒤 최종 스택 합 = 시작 스택 합 |
| 나누어 떨어지지 않는 칩 | 칩 단위·정수 스택이면 버튼 왼쪽 첫 승자부터 1칩씩 (가정). 그 밖은 정확히 나눔 |

## 3. 루루 판단 기록 (읽기 전용 가져오기)

입력: 루루 수집 도우미 "판단 기록 저장" 파일 `{ schema: 1, version, events: [...] }`. `kind: "decision"` 이벤트의 `input` 만 읽습니다.

| 기록 필드 | 처리 |
| --- | --- |
| `decisionHistory.handKey` | 같은 키의 이벤트를 한 핸드로 묶고, 액션이 가장 많은 이벤트의 이력을 씀 |
| `players`, 자리 이름 | 좌석 번호를 프리플랍 순서로 1..N 붙임 (실제 좌석 번호 아님 → `missing`) |
| `hero`, `hole`, `board` | 내 자리·카드·그 시점 보드 |
| `stacks` | **앤티를 뺀** 관측 스택+투자액(BB) → `observedStackAfterAnte`. 초기 스택은 `null` |
| `preflop/flop/turn/river` 의 `to` | 목표액(BB) 그대로. 콜 금액은 재구성 |
| `potBb`, `toCallBb`, `heroStackBb` | 스냅샷(대조용) |
| `output` (자동 판단) | 메모로만 남김. 실행 여부 미확인, 분석에 쓰지 않음 |
| 없는 것 | SB 금액, 앤티 종류·금액, 앤티 포함 초기 스택, 결과·쇼다운, 지급 구조·전체 필드 → `missing` |

BB 는 단위 정의상 1BB 로 넣습니다(관측 스택이 1BB 보다 작을 때만 그만큼). "편집 → 루루 기록 보완"에서 SB·앤티를 넣으면 `초기 스택 = 관측 스택 + 그 자리의 앤티` 로 만듭니다.

## 4. 프리플랍 자료 해석 (원본 코드와 대조)

자료: `public/lib/preflop/<id>.json` (`scripts/gen-preflop.ts` 가 `src/engine/ring.ts` 로 생성).

| 항목 | 뜻 | 근거 |
| --- | --- | --- |
| `nodes[i].p` | 행동하는 자리 (프리플랍 순서 번호) | `RingDecision.player` |
| `a[k] = [type, to, label, code]` | `to` = 이 액션 뒤 그 자리의 프리플랍 **누적 투자액**(블라인드 포함, 앤티 제외). 폴드의 `to` 는 이미 낸 금액 | `ring.ts` `add({ type, to: s2.invested[p] … })` |
| `s[k*169+c] / 1000` | 클래스 c 의 액션 k 빈도 | `gen-preflop.ts` `q = x*1000` |
| `e[k*169+c] / 100` | 액션 k 의 EV(BB), **그 노드에서 폴드 = 0 기준** | `RingSolver.evAt` 주석 "폴드=0"; 모든 노드에서 폴드 EV 가 0 임을 테스트로 확인 |
| `format.stack` | 앤티를 낸 **뒤** 남은 스택 | `stackLeft = cfg.stack − invested[p]`, 앤티는 팟에만 더함 |
| 169 클래스 | 13×13 그리드: 대각선 페어, 오른쪽 위 수딧, 왼쪽 아래 오프수트 (`classIndexFromRanks`) | 1,326 콤보 전수 대조 테스트 |

**정확 일치 조건** (하나라도 다르면 쓰지 않고 이유 표시)

- 8명 + 개인 앤티 0.125BB(자료 `mtt8-6/10/15/25/40/60`) 또는 6명 + 앤티 없음(`cash6-100`)
- SB 0.5BB, BB 1BB (BB 앤티는 불일치)
- 모든 자리의 `초기 스택 − 앤티` 가 자료 깊이와 같음 (±0.005BB). 가까운 깊이로 바꾸지 않음
- 프리플랍 액션을 트리로 따라갈 때 행동 자리가 같고, 레이즈·올인 목표액이 자료 액션의 `to` 와 ±0.005BB 안에서 **하나만** 맞음. 가까운 크기로 바꾸지 않음
- 자리 대응은 프리플랍 순서 번호로 함(6명 캐시 자료의 `UTG` = 이 앱의 6명 `LJ`)

### 판정 기준

| 경우 | 실수로 표시하는 조건 |
| --- | --- |
| 자료 비교 | 실제 액션이 자료 트리에 정확히 있고, 그 빈도가 5% 미만이고, 최대 EV 와의 차이가 0.05BB 초과. 내 핸드가 그 노드에 거의 오지 않으면(도달 1% 미만) 빈도는 학습되지 않은 값일 수 있어 EV 만 봄 |
| 콜하면 베팅이 끝나는 판단 | 콜 EV 의 절댓값이 max(표준오차 × 2, 0.01BB) 초과이고 실제 선택이 반대쪽. 리버에서 레이즈가 가능했으면 콜·폴드 중에서만 판정하고, 실제로 레이즈했으면 판정하지 않음 |
| 실제 선택의 EV 를 계산하지 못함 | 판정하지 않고 손실액을 만들지 않음 |

| 키 | 표시 | 언제 |
| --- | --- | --- |
| `amount` | 금액/단위 오류 | 금액 불일치, 최소 레이즈 미달, 스택 초과, 단위 오류 |

## 6. 계산·캐시·취소

- 계산은 Web Worker 에서 하고 작업마다 `jobId` 가 있습니다. 취소하면 표본·열거 루프가 다음 양보 지점(4,096회마다)에서 멈춥니다.
- 새 작업을 시작하거나 다른 핸드를 고르면 이전 작업은 취소되고, 늦게 온 응답은 `stale` 로 버립니다.
- 캐시 키 = SHA-256( 핸드 전체(카드·행동 경로·자리별 스택·블라인드/앤티·지급 구조·범위 가정) + 옵션(시드·표본) + 모델 버전 + 자료 7개의 해시 ).
- 같은 시드·표본이면 같은 결과가 나옵니다(`mulberry32` 난수).
