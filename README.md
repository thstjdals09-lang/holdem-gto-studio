# 홀덤 GTO 스튜디오

브라우저 안에서 전부 돌아가는 2~6인 홀덤 GTO 솔버 + 스터디 + 트레이너. 서버도 구독도 없습니다.

GTO Wizard의 제품 구조를 분석한 결과([gto-wizard-rea](https://github.com/thstjdals09-lang/gto-wizard-rea))와 오픈소스 솔버 조사를 바탕으로, 엔진은 **TypeScript로 새로 구현**했습니다(외부 솔버 코드 없음, AGPL 의존 없음).

## 기능

| 메뉴 | 내용 |
| --- | --- |
| 커스텀 솔브 | **플레이어 2~6인**, 플랍·턴·리버 시작 보드, 자리별 레인지(SB·BB·…·BTN 액션 순), 스트리트별 벳/레이즈 사이즈(팟 %), 레이크(%·캡), 올인 임계값, 최대 레이즈 수, 동크 허용(HU). 솔브 전 트리 크기·메모리·반복 시간 추정. 빠름/표준/깊음 프리셋(목표 익스플로잇어빌리티 + 반복 수 + 시간 예산), 중단·이어서 솔브 |
| 스터디 | 13×13 그리드에 전략(액션 비율 색), EV, 에퀴티, EQR 표시. 액션 리본으로 트리 탐색, 턴·리버 카드 선택, 상대 레인지 보기, 콤보 단위 빈도·EV 표. URL(`#/study?spot=…&path=…`)로 스팟·노드 재현 |
| 트레이너 | 솔브된 스팟에서 GTO 상대(평균 전략, 자기 핸드에 맞춘 혼합)와 플레이. 정확/부정확/블런더 판정, EV 손실(팟 %), GTO 빈도 피드백, 스트리트·자리별 통계, 드릴 저장(스팟+자리+시작 지점) |
| 프리플랍 랩 | HU(SB vs BB) 프리플랍 근사 솔버: 스택, 오픈·3벳·4벳 사이즈, 림프, 올인. 169 클래스 에퀴티 행렬(몬테카를로) 기반. 결과 레인지를 포스트플랍 솔브로 전달 |
| 계산기 | 레인지 vs 레인지 에퀴티(핸드별 히트맵), Malmuth-Harville ICM과 버블 팩터 |
| 에퀴티 러시 | 15초 안에 핸드 에퀴티를 맞히는 훈련 게임 |

## 엔진

- `src/engine/evaluator.ts`: 5~7장 핸드 평가기(비트마스크). 무작위 3000핸드에서 5장 조합 최댓값과 완전 일치 검증.
- `src/engine/range.ts`: 레인지 문법(`22+`, `A5s-A2s`, `T9s+`, `KK:0.5`, `AhKh`) 파서·직렬화.
- `src/engine/tree.ts`: 베팅 트리 빌더. 찬스 노드 아래 구조를 공유하고 런아웃별 전략 저장은 솔버가 담당.
- `src/engine/solver.ts`: 벡터화 Discounted CFR(α=1.5, β=0, γ=2, 교대 업데이트). 1326 콤보 reach 벡터, 카드 제거를 포함-배제로 정확히 반영한 O(n) 쇼다운 스윕, 최적 응답 기반 익스플로잇어빌리티, 평균 전략 직렬화/복원, 노드 분석(EV·에퀴티·EQR).
- `src/engine/multi.ts`: 멀티웨이(2~6인) 트리 빌더 + DCFR 솔버. 멀티플레이어 베팅 라운드(폴드·콜·체크·벳·레이즈·올인, 스트리트 종료 판정), 플레이어별 reach 벡터. 쇼다운/폴드 터미널에서 상대 조합 질량을 계산할 때 상대가 2명이면 카드 충돌(한 장 겹침·동일 콤보)을 포함-배제로 정확히 반영하고, 3명 이상이면 상대 간 겹침을 무시하는 독립 근사. 2인 입력은 HU 솔버와 동일한 값을 냄(테스트로 확인).
- `src/engine/preflop.ts`: 169 클래스 DCFR, 클래스 간 비충돌 콤보 수로 카드 제거 반영.
- `src/engine/equity.ts`, `src/engine/icm.ts`: 에퀴티·ICM.
- 모든 연산은 Web Worker(`src/worker/`)에서 실행. 결과는 IndexedDB에 저장.

검증(`npm test`, 29개): 리버 clairvoyance 게임이 이론값(너츠 100% 벳, 에어 50% 블러프 = 블러프:밸류 1:2, MDF 50% 콜)에 수렴, 레이크 0일 때 EV 합 = 팟 보존(리버·턴·플랍, 2인·3인), 턴 트리 익스플로잇어빌리티 감소, 멀티 솔버의 2인 결과가 HU 솔버와 일치, 3인 트리 구조(폴드 후 2인 쇼다운·전원 폴드 승자), HU 10bb 푸시/폴드 근사.

## 한계 (정직하게)

- 멀티웨이는 **4인 이상 쇼다운이 근사**(상대 간 카드 겹침 무시)이고, 폴드한 플레이어의 카드 제거(번칭)는 반영하지 않으며, 유효 스택이 전원 동일하다고 가정합니다(사이드팟 없음). 3인 이상에서는 CFR이 내시 균형을 보장하지 않으므로 결과는 "균형 근사"입니다. 반복당 비용이 HU보다 크므로 리버·턴 시작과 단일 사이즈를 권합니다.
- 플랍 시작 솔브는 메모리를 많이 씁니다(런아웃 수 × 노드 × 콤보). 추정치가 1.2GB를 넘으면 솔브 버튼이 막히므로 사이즈 수를 줄이거나 턴부터 시작하세요. 수트 동형(isomorphism) 병합과 16비트 압축은 아직 없습니다.
- 프리플랍 랩은 헤즈업 전용, 에퀴티 기반 근사입니다(포스트플랍 플레이·포지션 이점 미반영).
- 단일 스레드 워커입니다. 멀티스레드(SharedArrayBuffer)는 다음 단계.
- 핸드 히스토리 업로드·분석기는 없습니다.
